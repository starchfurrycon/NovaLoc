## 二、指标 1：翻译覆盖率

24 条失败**全部被拦下并保留原文**（没有一条以"看起来像译文"的形式写回）：

| 失败原因 | 条数 | 含义 |
|---|---|---|
| `placeholder_broken` | 14 | 译文丢了 `\V[n]` 之类的**内容类**占位符 ⇒ 游戏里会显示错数据 |
| `prompt_leak` | 5 | 模型把提示词/元文本当译文吐出来了 |

| `repetition` | 2 | 译文退化成重复串 |

### 关键取舍：占位符分两类

MV 的转义符不是一回事，混为一谈会误伤：

| 类别 | 符号 | 丢了会怎样 | 处理 |
|---|---|---|---|
| **纯样式** | `\{ \} \! \. \| \> \< \^ \\` | 只影响加速/停顿/缩放等显示效果 | **允许丢**，不算失败 |
| **内容** | `\V[n] \N[n] \P[n] \C[n] \I[n] \S[n] \D \R \$ \G` | 变成错数据/错图标 ⇒ **致命** | **丢了判失败**，保留原文 |

不加这条区分，合并句的误判率是 **8/29 = 27.6%**；加了之后降到
**3/29 = 10.3%**，全部 215 条带占位符的条目里只有 **3 条（1.4%）** 判失败。

### 一个**反例**判据：重复检测不能跨语言

拟声词 `*Pant* *Pant* *Pant*` 译成 `喘… 喘… 喘…` 会被字符级 n-gram
判成"退化重复"。实测抽检的 12 条此类失败**全部是忠实翻译**。
现在的规则是：**源文自己就有 4-gram 重复 ≥3 次时，跳过重复检测** ——
那是作者的手法，不是模型坏了。

### 设计红线：贴图文字**绝不**由生成模型直出

流程固定为 **检测 → OCR → inpaint 抹字 → 用真实中文字体按原风格重绘**。
生成模型只在"艺术字"兜底场景下可选启用。

原因不是保守：生成模型写汉字**会写出形近的错字**（笔画多一笔少一笔），
而且**不可验证** —— 你没法自动判断它写的是不是你要的那个字。
inpaint + 真字体重绘的产物可以用 OCR 回读**客观验收**（上表就是这么来的）。

## 四、指标 3：字体缺失 / 口口口

`10/10` 个字体覆盖率全部 **100%**，QA 空白字形 **0**。

### 这一项修掉了四类"覆盖率报 100% 但游戏里是空白"的假成功

#### (1) base 的 cmap 有码点，但字形是**空的**

合并的默认判据是 `needed = required - base.cmap` —— base 的 cmap 里有
这个码点就认为它有字形。**日文手写体不满足这个假设**：

* `koin.ttf` cmap 里 21,363 个码点，抽样 400 个常用汉字里
  **39 个字形是空的**（`到你而那之如没些她但只从`）；
* 真实文本需要的 3,596 个字里，**2,164 个**在 base 里是空字形。

于是合并"成功"、覆盖率 100%、QA 数出 **1,258 个空白**。
修法：先按原判据合 → QA 渲染验证 → **只把验证失败的那些**强制覆盖重合一次
（不能一上来就全覆盖，那等于放弃"保留原字体风格"）。

#### (2) 「强制」本身不生效 —— `Merger` 保留 base 那一条

把字符放进 `needed` 不够。实测强制与不强制产出的 `¢` **字形名一样**
（都是 base 的 `cent`）。修法：把强制字符**从 base 的 cmap 里摘掉**，
且必须遍历**所有** cmap 子表（游戏引擎和 Pillow 会挑不同子表）。

#### (3) 摘 cmap 之后规划器选的字体不够用了

摘掉 2,217 个空字形后 `✔✕✖✘❤` 变成缺字，而规划器只选了一个不含它们的
字体 ⇒ 报"仍缺 5 个字符" ⇒ 整个重试被丢弃 ⇒ **2,217 个空白原样保留**。
修法：重试时传**全部候选**，而不是规划器当初选的那一个。

#### (4) QA 把「可放弃的装饰符号」也算成失败

规划器按两层放行了本机任何字体都没有的装饰符号（`¢¥µ·¿í ※ ‥ ′ ″`），
QA 却把它们算成"空白"而硬失败 —— 自相矛盾。症状极具误导性：
日志说"空白 1259"，实际那 1259 个里绝大多数**玩家永远看不到**
（在 45,943 条文本里出现 **0 次**）。修法：`verify_font` 只校验
`required`，`optional` 的空白单独记一条警告。

#### (5) CFF（`.otf`）字体合并不了 ⇒ 退化为「整体替换」

`ship.otf` 是 CFF 轮廓，合并器要求 `glyf`/`loca`。原先直接失败 ⇒
字体原样留着（**只有 77.2% 中文覆盖**）⇒ 游戏里凡用到它就是口口口。
现在退化为整体替换成覆盖最好的中文字体。

只有**确实是 CFF** 时才退化（判据是错误信息里同时有 `glyf` 和 `loca`），
别的合并失败照旧上报 —— 否则真正的规划错误会被"替换"掩盖。

> 顺带一条教训：**"没被 CSS 引用"不等于"游戏不会用到"**。
> 这个游戏的 `FontLoad` 插件用 `Graphics.loadFont()` 动态加载字体，
> 不走 `@font-face`。所以按"宁可不缺字"处理。

## 五、指标 4：回写保真度

```
应写                45,548
逐槽位拼回完全一致  45,218
换行落在槽位边界     330      ← 正确行为（模型自己的断行）
真正不一致             0
字符级丢字             0
产物缺失的数据文件     0 / 443
```

### 这一项修掉的是**最危险的一类 bug**：静默部分丢弃

第一次 apply 的输出是：

```
⚠ 定位失败：Scenario.json/1/list/73/parameters/0     ← 只显示 100 条
✅ 回写产物 完成：已写入 644 个文件
🎉 全部完成。可玩目录：…
```

看起来"有几个位置没找到"。实际是 **23,159 条剧情对白一条都没写进去**。

原因：`Scenario.json` 的真实结构是 `{"1": [ {code:401,…} ]}`（**没有
`list` 那一层**），而 `extracted/units.jsonl` 是修 `/list/` bug **之前**
抽的，指针还是旧格式 —— 没跟着重抽。

**为什么整条流水线都没拦住**：

| 判据 | 为什么没响 |
|---|---|
| `files_written` 只在 `n > 0` 时自增 | 644 个文件确实写成功了 |
| `files_all_failed`（整文件全失败） | `Scenario.json` **写进去过**一条 ⇒ 不在名单里 |
| `slot_failed > 0` 只打 warning | 23,159 条 warning 淹没在日志里 |

用户拿到的是"菜单是中文、剧情全是原文"的游戏，**所有计数都显示成功**。

修法：判据落到**槽位**一级，失败占比 **> 1%** 时**硬失败**并给出可操作
指引。取 1% 而非 0：偶发个别失败（源文件被手改过、事件结构特殊）不该
一票否决；而结构性错配会命中**成百上千**条。

### 第二个缺陷：模型自己保留的换行被吃掉、然后按字符数硬切

修好指针后仍有 330 条回读不一致，全是"源文多行"的 unit：

```
source = 'Migrant:\nI made the right choice when I moved here with my family.'
target = '移民：\n只返回 JSON：…'        ← 模型自己带 \n
老写入 = ['移民：', '只返回 JSON：…']     ← 吃掉 \n 再均分
```

MV 的 401 参数**就是**消息框里的一行，模型看到 `\n` 会自然保留 ——
那个断行位置就是作者定的版面。老代码把它丢掉、自己重新找切点，
于是 `'大猩猩：\n只有你能做到！'` 分 3 格会切成
`['大猩', '猩：只有', '你能做到！']` —— 把"大猩猩"从中间劈开。

修法：**优先用模型自己的断行**；只有当译文是一整行时才按**源文各行的
长度比例**找切点（现成的版面信息），而不是按字符数均分。

批量翻译的两次关键优化（都是**实测**驱动的）：

1. **提示词形状**：`[{"i":N,"t":"…"}]` 会让 `translategemma:4b` 只输出
   **一个**对象就停（4/8/16/24/40 条请求全部只回 1 条，约 26 token，
   `done_reason=stop`）。改成数字键对象 `{"0": "译文", …}` 后 **40/40 通过，
   10.1 秒**。
2. **长文本阈值 60 → 200 字符**：真实 MV 文本长度中位数 50、p90 67、
   最大 159；`>60` 的占 **34.8%**。放宽后请求数从 **20,709（平均 1.7 条）
   降到 1,449（平均 23.7 条）= 少 14.3 倍**。

## 八、已知限制

* **Unity**：TMP 字体图集需要重烘焙才能注入字形，v1.0 只做字符串扫描；
  见 `docs/ROADMAP.md` §2.5。
* **UI 缩写撞词**只是 **WARN**，不拦流程。实测 DemonsRoots 命中 2 组，
  两组都是**正确**翻译（`'是的。' ← Aye./Yes.`、`'治疗药' ← Cure/Heal`）。
  按结构细化**分不开**（`Aye.`/`Yes.` 与 `HP`/`MP` 同长，特征一样），
  所以选择"列出但不拦" —— **拦下正确产物比漏放一个可疑项更糟**。
* **105 条译文含日文假名**，全部是内部事件标识符（非玩家对白），
  需要假名字形覆盖（已包含在字符集里）。
* 贴图汉化只对**检测到文字**的贴图动手；纯背景/立绘不改（192/1,141 说明
  其余是无可汉化文字或检测未命中）。
* 合并 / 替换策略**不保留**原字体的字形风格（这是 `merge` 之外的取舍，
  见 `docs/FONTS.md`）。

## 九、复现方式

```powershell
# 1. 建立项目（原始游戏目录只读）
novaloc project new "D:\path\to\game"

# 2. 全流水线
novaloc run <workspace-id>

# 3. 只重跑某一阶段（改完字体/译文后）
novaloc run <workspace-id> --stage fonts --force
novaloc run <workspace-id> --stage apply

# 产物：<data_root>\workspaces\<id>\out
```

字体缓存与模型都在**仓库之外**（`D:\NovaLoc\fonts\cache`、
`D:\NovaLoc\models`）—— 仓库里**不含任何字体文件和模型文件**。
