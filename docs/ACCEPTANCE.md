### 关键取舍：占位符分两类

MV 的转义符不是一回事，混为一谈会误伤：

| 类别 | 符号 | 丢了会怎样 | 处理 |
|---|---|---|---|
| **纯样式** | `\{ \} \! \. \| \> \< \^ \\` | 只影响加速/停顿/缩放等显示效果 | **允许丢**，不算失败 |
| **内容** | `\V[n] \N[n] \P[n] \C[n] \I[n] \S[n] \D \R \$ \G` | 变成错数据/错图标 ⇒ **致命** | **丢了判失败**，保留原文 |

不加这条区分，合并句的误判率是 **8/29 = 27.6%**；加了之后降到
**3/29 = 10.3%**，全部 215 条带占位符的条目里只有 **3 条（1.4%）** 判失败。

### 一个**反例**判据：重复检测不能跨语言

拟声词 `*Pant* *Pant* *Pant*` 译成 `喘… 喘… 喘…` 会被字符级 n-gram
判成"退化重复"。实测抽检的 12 条此类失败**全部是忠实翻译**。
现在的规则是：**源文自己就有 4-gram 重复 ≥3 次时，跳过重复检测** ——
那是作者的手法，不是模型坏了。

### 设计红线：贴图文字**绝不**由生成模型直出

流程固定为 **检测 → OCR → inpaint 抹字 → 用真实中文字体按原风格重绘**。
生成模型只在"艺术字"兜底场景下可选启用。

原因不是保守：生成模型写汉字**会写出形近的错字**（笔画多一笔少一笔），
而且**不可验证** —— 你没法自动判断它写的是不是你要的那个字。
inpaint + 真字体重绘的产物可以用 OCR 回读**客观验收**（上表就是这么来的）。

## 四、指标 3：字体缺失 / 口口口

`10/10` 个字体覆盖率全部 **100%**，QA 空白字形 **0**。

### 这一项修掉了四类"覆盖率报 100% 但游戏里是空白"的假成功

#### (1) base 的 cmap 有码点，但字形是**空的**

合并的默认判据是 `needed = required - base.cmap` —— base 的 cmap 里有
这个码点就认为它有字形。**日文手写体不满足这个假设**：

* `koin.ttf` cmap 里 21,363 个码点，抽样 400 个常用汉字里
  **39 个字形是空的**（`到你而那之如没些她但只从`）；
* 真实文本需要的 3,596 个字里，**2,164 个**在 base 里是空字形。

于是合并"成功"、覆盖率 100%、QA 数出 **1,258 个空白**。
修法：先按原判据合 → QA 渲染验证 → **只把验证失败的那些**强制覆盖重合一次
（不能一上来就全覆盖，那等于放弃"保留原字体风格"）。

#### (2) 「强制」本身不生效 —— `Merger` 保留 base 那一条

把字符放进 `needed` 不够。实测强制与不强制产出的 `¢` **字形名一样**
（都是 base 的 `cent`）。修法：把强制字符**从 base 的 cmap 里摘掉**，
且必须遍历**所有** cmap 子表（游戏引擎和 Pillow 会挑不同子表）。

#### (3) 摘 cmap 之后规划器选的字体不够用了

摘掉 2,217 个空字形后 `✔✕✖✘❤` 变成缺字，而规划器只选了一个不含它们的
字体 ⇒ 报"仍缺 5 个字符" ⇒ 整个重试被丢弃 ⇒ **2,217 个空白原样保留**。
修法：重试时传**全部候选**，而不是规划器当初选的那一个。

#### (4) QA 把「可放弃的装饰符号」也算成失败

规划器按两层放行了本机任何字体都没有的装饰符号（`¢¥µ·¿í ※ ‥ ′ ″`），
QA 却把它们算成"空白"而硬失败 —— 自相矛盾。症状极具误导性：
日志说"空白 1259"，实际那 1259 个里绝大多数**玩家永远看不到**
（在 45,943 条文本里出现 **0 次**）。修法：`verify_font` 只校验
`required`，`optional` 的空白单独记一条警告。

#### (5) CFF（`.otf`）字体合并不了 ⇒ 退化为「整体替换」

`ship.otf` 是 CFF 轮廓，合并器要求 `glyf`/`loca`。原先直接失败 ⇒
字体原样留着（**只有 77.2% 中文覆盖**）⇒ 游戏里凡用到它就是口口口。
现在退化为整体替换成覆盖最好的中文字体。

只有**确实是 CFF** 时才退化（判据是错误信息里同时有 `glyf` 和 `loca`），
别的合并失败照旧上报 —— 否则真正的规划错误会被"替换"掩盖。

> 顺带一条教训：**"没被 CSS 引用"不等于"游戏不会用到"**。
> 这个游戏的 `FontLoad` 插件用 `Graphics.loadFont()` 动态加载字体，
> 不走 `@font-face`。所以按"宁可不缺字"处理。

## 五、指标 4：回写保真度

```
应写                45,548
逐槽位拼回完全一致  45,218
换行落在槽位边界     330      ← 正确行为（模型自己的断行）
真正不一致             0
字符级丢字             0
产物缺失的数据文件     0 / 443
```

### 这一项修掉的是**最危险的一类 bug**：静默部分丢弃

第一次 apply 的输出是：

```
⚠ 定位失败：Scenario.json/1/list/73/parameters/0     ← 只显示 100 条
✅ 回写产物 完成：已写入 644 个文件
🎉 全部完成。可玩目录：…
```

看起来"有几个位置没找到"。实际是 **23,159 条剧情对白一条都没写进去**。

原因：`Scenario.json` 的真实结构是 `{"1": [ {code:401,…} ]}`（**没有
`list` 那一层**），而 `extracted/units.jsonl` 是修 `/list/` bug **之前**
抽的，指针还是旧格式 —— 没跟着重抽。

**为什么整条流水线都没拦住**：

| 判据 | 为什么没响 |
|---|---|
| `files_written` 只在 `n > 0` 时自增 | 644 个文件确实写成功了 |
| `files_all_failed`（整文件全失败） | `Scenario.json` **写进去过**一条 ⇒ 不在名单里 |
| `slot_failed > 0` 只打 warning | 23,159 条 warning 淹没在日志里 |

用户拿到的是"菜单是中文、剧情全是原文"的游戏，**所有计数都显示成功**。

修法：判据落到**槽位**一级，失败占比 **> 1%** 时**硬失败**并给出可操作
指引。取 1% 而非 0：偶发个别失败（源文件被手改过、事件结构特殊）不该
一票否决；而结构性错配会命中**成百上千**条。

### 第二个缺陷：模型自己保留的换行被吃掉、然后按字符数硬切

修好指针后仍有 330 条回读不一致，全是"源文多行"的 unit：

```
source = 'Migrant:\nI made the right choice when I moved here with my family.'
target = '移民：\n只返回 JSON：…'        ← 模型自己带 \n
老写入 = ['移民：', '只返回 JSON：…']     ← 吃掉 \n 再均分
```

MV 的 401 参数**就是**消息框里的一行，模型看到 `\n` 会自然保留 ——
那个断行位置就是作者定的版面。老代码把它丢掉、自己重新找切点，
于是 `'大猩猩：\n只有你能做到！'` 分 3 格会切成
`['大猩', '猩：只有', '你能做到！']` —— 把"大猩猩"从中间劈开。

修法：**优先用模型自己的断行**；只有当译文是一整行时才按**源文各行的
长度比例**找切点（现成的版面信息），而不是按字符数均分。

## 五之二、多行条目的**静默丢内容**（v1.0.1 修，最严重的一个）

RPG Maker 有 **48%** 的对话是"一条台词被引擎按显示宽度切成多个 401 指令"。
适配器把这种组**合成一条** TextUnit 送翻译（分开翻只能得到半句话），
译完再按行拆回各槽位。

### 根因：模型**看着换行自己切条**

裸调 Ollama 抓到的直接证据（`.scratch/_dump_raw_ollama.py`）：
提示词给的是编号 **0~3** 共 4 条，`translategemma:4b` 却吐出了 **`"4"`** 这个键：

```json
{"0": "…", "1": "…", "2": "…", "3": "…", "4": "更多文字在此。"}
```

它把同一条目里的多个换行当成了多个条目。后果两条：

1. **编号整体错位** —— A 条的内容落进 B 条；
2. **一条 3 行的台词只翻出第 1 行**。

而这两种都**通顺、长度比也不越界**（英→中字符数比中位数本来就是 0.296），
所有检查全绿 —— 正是 §五 说的"最危险的一类 bug：静默部分丢弃"。

### 量化（以"逐行拆开单独翻再拼起来"为内容量参照，它不会丢行）

20 条真实多行英文文本（平均 116 字符 / 2.4 行）：

| 模型 | 合并送（修前） | 屏蔽换行后 |
|---|---|---|
| `translategemma:4b` | 中位数 **0.33~0.70**，1 条空 | **0.87**，快 15% |
| `HY-MT1.5-7B` | 0.75~0.94，**5 条空译文** | **1.03**，**0 条空**，快 50% |

### 修法：把换行也当占位符屏蔽（`translate.mask_newlines = True`）

`\n` → `⟦n⟧`，模型眼里每条只剩一行，没得切。两个模型都明显变好，而且更快
（少一次逐条降级）。`mask()` 的 `newlines` 参数默认 `False`，所以老行为没变。

### 配套：`verify_restored` 补了**第四层**校验

换行屏蔽要兑现"丢行 → 硬失败"这个价值，必须能发现"模型把记号删了"。
实测发现**原来的三层校验全漏**：

* `compare_restored(original, restored)` 比的是"原文 vs 还原后"。
  模型把某个记号整个删了，还原后两边都没有那个点位的东西 → "相等"、不报错。
* 顺序校验要求 `src_order and tgt_order` 都非空。只丢到"一个记号都不剩"时
  `tgt_order == []`，整个分支被跳过 —— 恰好是最严重的情形静默通过。

实测：源 `"第一行\n第二行"` 屏蔽成 `"第一行⟦0⟧第二行"`，
模型只回 `"只翻了第一行"`，三层校验**全绿**。

新增第 4 层按**记号索引集合**判缺失/多余。两个坑（都是撞出来的）：

* **只对"内容类"记号报缺失**。纯样式记号（`\{` `\}` `\|` `\.` `\!` `\<`
  `\>` `\^` `\\`）与 `%%` 历史上**允许丢** ——
  `test_placeholder_consistency.py` 有一整组用例专门守这个。
  第一版写成"所有记号都要回来"，那 8 条用例立刻全红。
* **"模型把原始占位符原样抄回来"是合法输出**（多重集一致，其实帮了忙），
  不能判成"多余"或"缺失"。`test_placeholders.py` 明确标了这种应当通过。第一版把它判死。

### 顺带修掉两个潜伏崩溃

| 缺陷 | 后果 |
|---|---|
| `self.cfg.translate.max_output_chars_factor`（配置里**没有**这个字段） | 一旦走到"记号重试"就 `AttributeError`，**整批补救作废**。正常路径不经过，单元测试与历史实测都没碰到，换模型后才暴露 |
| "连续内容记号组被拆散"判据缩进在 `elif left:` 里 | 产品路径**全都传** `masked_source`，所以这个判据**从来没跑过** —— 它是"图标码组被拆开"的**唯一**拦截点。静默失效的后果是 `\I[96]` 跑到别的标签后面，玩家看到"防具类型"配武器图标 |

## 五之三、提示词回声：模型把"翻译要求"当成要翻译的内容

`build_batch_user_prompt` 里风格规则写成 `  · 编号 0, 3, 7：<规则>` ——
**和载荷 `i → 原文` 形状一样**，于是模型分不清规则和内容。

36 条真实英文多行文本、`demonbyron/HY-MT1.5-7B` 实测：**2/36 条直接把规则原文
当译文输出**：

```
KIND_HINT[DIALOGUE] 的规则文字 → 出现在"译文"里
```

只改提示词形状（载荷包 `<原文>…</原文>`、规则段标"这不是待翻译的内容"）
只把泄漏从 **2 条降到 1 条** —— **不够**。所以最后是**产品侧守卫**兜住。

### 判据方向是决定性的：量"提示词被覆盖了多少"，不是"译文里有多少提示词"

| 判据 | 正常译文 | 真泄漏 |
|---|---|---|
| 交集 / 译文 n-gram 数 | 44.4% | 44.4% ← **分不开** |
| **交集 / 提示词 n-gram 数（采用）** | **4.7%** | **44.2%** |

反方向差了一个数量级，阈值取 `0.35`。多尺度 n-gram（2/3/4）取最大覆盖，
因为改写式回声（`保持→请保持`、`若是→如果`、`与→和`）会把 4-gram 重合压到阈值以下。

**短译文必须豁免**（`_HINT_MIN_TARGET_BIGRAMS = 8`）：`"攻击"` 只有 1 个 bigram，
而 `UI_LABEL` 规则里正好拿 `Attack→攻击` 当例子 → 100% 重合，
所有 ≤5 字的标签会全部误报。代价是最露骨的那条泄漏（`"中文译文"`，2 字）也不报了 ——
**宁可漏报一个，不能把标签全判死**。

### 实测

* 策展集（5 条真泄漏 + 13 条正常）：**0 漏 / 0 误报**
* 已上线译文里等距抽 **3,037** 条：**误报 0.000%**

  （`敏捷性` `防御力` `精神力` `特技` `魔法` `斧` `弓` `盾` `兜` …）——
  切片恰好等于源文，不是漏写
* 1 条 `failed` 是守卫**正确拦下**的（丢失 `\C[0]` `\C[2]` `\V[10]` 三个内容记号），
  按判据不留坏译文

## 七、吞吐

| 阶段 | 规模 | 耗时 |
|---|---|---|
| 翻译 | 7,434 unit | 60 min 26 s（**7,400–7,800 条/小时**） |
| 贴图汉化 | 1,141 张 | 7 min 13 s |
| 字体适配 | 10 个字体 | 约 2 min |
| 回写 | 443 个数据文件 | 16 s |
| 质检 | 45,572 条 | 0.9 s |

批量翻译的两次关键优化（都是**实测**驱动的）：

1. **提示词形状**：`[{"i":N,"t":"…"}]` 会让 `translategemma:4b` 只输出
   **一个**对象就停（4/8/16/24/40 条请求全部只回 1 条，约 26 token，
   `done_reason=stop`）。改成数字键对象 `{"0": "译文", …}` 后 **40/40 通过，
   10.1 秒**。
2. **长文本阈值 60 → 200 字符**：真实 MV 文本长度中位数 50、p90 67、
   最大 159；`>60` 的占 **34.8%**。放宽后请求数从 **20,709（平均 1.7 条）
   降到 1,449（平均 23.7 条）= 少 14.3 倍**。

## 八、已知限制

* **Unity**：分两种情况，**实测澄清了其中的误解** ——
  * 若游戏走 **TextMeshPro**：TMP 用**预烘焙图集**渲染文字，换 TTF
    **不生效**，必须重新烘焙图集。本项目**未实现**重烘焙，
    见 `docs/ROADMAP.md` §2.3。
  * 若游戏走**传统 uGUI**（实测所用的真实 Unity 游戏就是这种，
    全目录搜 `TMP_FontAsset` 零命中）：**没有这道坎**，字体替换路径
    正常。所以"Unity 一定需要重烘焙"这个说法**不成立**。
  * 无论哪种，**文本若在 `.assets` 序列化资源里就仍不支持**（实测确认
    真实游戏的对白确实在那里，DLL 里只有内部消息）。可用 UABEA /
    AssetStudio 导出后走散装文件模式。
* **逐行送翻会漏进原文的拉丁词**：实测 `translategemma:4b` 吐出过
  `「邪恶之 bane」`（原词泄漏）。现有守卫**抓不住**这种泄漏 ——
  它既不是异体字脚本，也不触发重复/长度判据。属于**质量瑕疵而非
  静默丢内容**，仍需人工审校。这是当前**逐行兜底**唯一的已知代价。
* **`units.jsonl` 没有"抽取代码版本"标记**：旧版适配器抽的结果会一直
  躺着，而所有覆盖率数字的分母都依赖它。实测因此出现过
  **1,343 vs 6,758** 的分母错误（差 5,415 条剧情对白，全部来自
  `CommonEvents.json`）—— 也就是说**先前基于 1,343 条的覆盖率结论
  分母都是错的**。修法是写 `extractor_version` 并在不符时警告，
  见 `docs/ROADMAP.md` §3.23。
* **UI 缩写撞词**只是 **WARN**，不拦流程。实测 DemonsRoots 命中 2 组，
  两组都是**正确**翻译（`'是的。' ← Aye./Yes.`、`'治疗药' ← Cure/Heal`）。
  按结构细化**分不开**（`Aye.`/`Yes.` 与 `HP`/`MP` 同长，特征一样），
  所以选择"列出但不拦" —— **拦下正确产物比漏放一个可疑项更糟**。
* **105 条译文含日文假名**，全部是内部事件标识符（非玩家对白），
  需要假名字形覆盖（已包含在字符集里）。
* 贴图汉化只对**检测到文字**的贴图动手；纯背景/立绘不改（192/1,141 说明
  其余是无可汉化文字或检测未命中）。
* 合并 / 替换策略**不保留**原字体的字形风格（这是 `merge` 之外的取舍，
  见 `docs/FONTS.md`）。
* **视觉兜底（VLM）默认关闭，且不建议开启** —— 理由见下节。

## 八之二、为什么不用生成模型去读/写文字（实测）

这条是**设计红线**，不是实现取舍。它有两半：**读**（OCR 兜底）和
**写**（贴图重绘）。

### 读：VLM 在无文字输入上会**编造**

`ocr.vlm_fallback` 默认 `False`。这个默认值曾建立在一次**工具坏掉**的
测量上（提示词要求 bbox 但调用方丢弃坐标、调用方又追加一条互斥的
"只输出文字本身"、没有 `num_predict` 上限）。修掉之后重测，
结论**依然是关**，但理由变成了"它会编造"：

| 输入（同一模型、同一提示词） | 输出 |
|---|---|
| 纯白 200x60 | `'Now Loading...\n-Demons Roots-'` |
| 近白噪声 200x60 | `'Now Loading...\n\n-Demons Roots-'` |
| 极小 34x12 纯白 | `'Now Loading...\n-Demons Roots-'` |
| 写有 `GAME OVER` | `'GAME OVER'` ← **只有这张是对的** |

**在完全没有文字的空白图上，它稳定编造出本游戏加载画面上的那行字。**
它在"补全一个像样的贴图文字"，而不是在**读**。而"低置信块"恰恰就是
小图标、被 inpaint 擦过一半的区域、低分辨率裁剪这类输入 ——
正是兜底要去处理的对象。

真实 DemonsRoots 上重扫（40 张 / 295 块）：置信度 `<0.6` **9.5%**、
`0.6-0.8` **16.9%**（低置信块确实存在，"很少触发"不成立）；
对 30 个 `conf < 0.8` 的块逐块重读：
**变好 0 / 变差 0 / 持平 3 / 被质量闸门拒 16 / 空结果 11**，平均 13.4 秒/块。
按 8 次/图 × 192 张 = 1,536 次估算 ≈ **5.7 小时**，换来的是编造。

修好的部分仍有价值（旧组合实测 **21.9 秒**已超过默认超时 20 秒 ⇒
对开启该选项的用户来说这个功能原本**从来没生效过**；现在是 15.1 秒
且输出干净），但那只是让一个默认关闭的选项**可用**，不是可信。

### 写：贴图文字**只**做 inpaint + 真实字体重绘

同一理由。让生成模型"只把贴图里的文字换成中文"在演示里很好看，
但它填的是"先验上像什么"，**真值对不对它无从判断** ——
无法保证不改动画面、无法保证不新增文字、无法保证译文正确。
所以贴图管线是 `检测 → inpaint 去字 → 用真实 CJK 字体重绘`
（§三），全程没有生成模型参与像素生成。

### 一个反复出现的教训

本项目里**"测量工具坏了"至少发生过四次**，每一次都差点改掉正确的默认值：

1. **视觉兜底**（本节）：旧数据说"0 变好 / 其余读不出"，实际是
   21.9 秒必然超时返回空串；
2. **重复度判据**（§二）：源文 `*Pant* *Pant* *Pant*` 的**忠实翻译**
   `喘… 喘… 喘…` 被当成"重复生成失败"，12/12 抽样全是误判；
3. **长度比阈值**（§五之二）：本想用"译文/源文长度比 < 0.5 = 截断"来抓丢句。
   在 26,605 条**已上线**译文上量：中位数 **0.296**、p10 **0.069**、p90 **0.412** ——
   中英字符数比本来就这么小（英文一个词译成一个字），`< 0.5` 把
   **58/60 条正常译文**判成截断。真实的丢句问题因此一直被漏掉，
   最后是靠"逐行拆开单独翻再拼起来"当参照才量出来；
4. **VX 回写核对器**（§六）：把 Hash 的整数键写成 `[@1]`、而真实指针是 `@1`
   （`_step` 会 strip 掉 `@` 再比，所以两种写法等价但字符串不等）。
   核对器因此把 **184 处完全正确**的改动报成"改动了不该改的地方"。

第 3 条和第 4 条的形状一样：**判据/工具本身没在真实样本上验过**。
所以凡是要据以改默认值的结论，都必须先问
"这个判据在真实数据上量过吗、量出来的数合不合理"。
第 3 条尤其值得记：它不报错、不崩溃，只是**静默地把真问题滤掉了**。

## 九、复现方式

```powershell
# 1. 建立项目（原始游戏目录只读）
novaloc project new "D:\path\to\game"

# 2. 全流水线
novaloc run <workspace-id>

# 3. 只重跑某一阶段（改完字体/译文后）
novaloc run <workspace-id> --stage fonts --force
novaloc run <workspace-id> --stage apply

# 产物：<data_root>\workspaces\<id>\out
```

字体缓存与模型都在**仓库之外**（`D:\NovaLoc\fonts\cache`、
`D:\NovaLoc\models`）—— 仓库里**不含任何字体文件和模型文件**。
