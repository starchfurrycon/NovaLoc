## 六、RPG Maker 真实库测试：`auto` 自动发现 + 就地写回（本轮新增）

上面那一节是**单**个 Unity 游戏。这一节是被测出来的"**全自动**"
能力 —— 给一个**目录**，`auto` 自己找出里面的游戏、自己判断引擎。

### 6.1 命令与结果

测试库是个**只有 2 个游戏**的目录，刻意**不点名任何游戏**：

```

```

发现阶段（自动识别引擎，无需配置）：

```
找到 2 个候选游戏目录
待处理 2　已是中文 0　识别失败 0　待处理引擎分布：rpgmaker 2
```

游戏 1 完成：

```
✅ done　条目 5457（译 4885）　贴图 243　用时 107 分 18 秒
   写回 65 个文件，备份在 D:\NovaLoc\_novaloc_backup\Dungeon And Darkness-Steam-20261002-203430
```

### 6.2 逐文件备份核对（这是本节的核心结论）

用 `.scratch/_e2e_auto_verify.py` 做**逐文件**核对，而不是
"备份里存在某个同哈希文件就算过"（后者太弱：1 个匹配就能让断言通过，
即使另外 60 个被改的文件根本没备份）。写回是**不可逆**操作，
断言必须与实际改动**一一对应**：

```
=== 文件变化 ===
   未变 4058   改了 61   新增 4   删除 0
=== 备份核对（逐文件）===
   备份根下有 2 个目录
   被改文件 61 个：有备份 61，**无备份** 0
=== 判定 ===
   ✅ 就地写回生效（61 个文件），且每个都有可回滚备份
```

* **就地写回生效**：测试库里有 **65 个文件被就地改写**（61 个内容变化的
  `.json` + 字体等产物）；
* **每一个被改文件都能回滚**：备份里存在与"改动前 SHA256"**完全一致**的副本；
* rpgmaker 的 `.json` 大小**允许变化**（不是 Unity 那种等长约束），
  实测 61 个里有 61 个大小变了 —— 这是预期。

### 6.3 ★ 这一步先暴露的是**我自己验证脚本的 bug**

第一次跑核对时输出的是：

```
被改文件 61 个：有备份 0，**无备份** 61
   ✗ 有 61 个被改文件**没有**对应的改动前备份 —— 不可回滚
```

看着像**严重产品缺陷**（61 个文件全不可回滚）。但去翻备份目录：

```
[dir]  \www
[dir]  \www\data
[file] \www\data\Actors.json  7614B   ← 与改动前字节数一致
```

**备份一直都在，而且是对的。** 问题在路径拼接：

| | 路径形态 |
| --- | --- |
| 备份里的 | **游戏根相对**：`www\data\Actors.json` |
| 快照的 key | **库根相对**：`Dungeon And Darkness-Steam\www\data\Actors.json` |

脚本只试了后者，于是**每一个**文件都判成"无备份"。
修法是两种都试（先原样，再去掉库根那一段游戏名）。

教训：**"断言失败"和"产品有问题"是两件事** ——
一个全量失败的断言，先怀疑断言本身（这里是 61/61 全红，
"每个都错"本身就是断言写错的强信号）。

### 6.5 重跑时的一个**自动跳过**证据（本轮新增）

游戏 1 写回成功之后，我又对**同一个库**跑了一次 `auto`（本轮为了
量另一个问题而重启的）。这一次的输出是：

```
扫描游戏库 E:\lush\1\_novaloc_test_lib
  找到 2 个候选游戏目录，正在识别引擎…

  待处理 1　已是中文 1　识别失败 0
  待处理引擎分布：rpgmaker 1
─────────────────────── [1/1] Midnight Exhibitionist DX ───────────────────────
  引擎 rpgmaker　E:\lush\1\_novaloc_test_lib\Midnight Exhibitionist DX
```

**注意 `已是中文 1` 与 `[1/1]`**：上一轮已经汉化过的
`Dungeon And Darkness-Steam` 这次**被识别为"已是中文"并跳过**，
只剩未汉化的 `Midnight Exhibitionist DX` 待处理。

这证明了两件事：

1. **重跑是幂等的** —— 不会把已经汉化过的游戏再翻一遍（那样会
   造成二次翻译、把中文再"译"一次而破坏内容）；
2. **`auto` 的"新加游戏"路径是真的** —— 它按**当前库内容**决定
   待处理集合，而不是靠一份需要手工维护的清单。

⚠️ 边界：这证明的是"跳过已完成的游戏"，**不是**"能正确处理
半个游戏被汉化过的情况"（那种情况本轮没构造）。

## 七、本记录**没有**证明的事（诚实边界）

1. **没有启动游戏本体验证画面**。本次只做到"文件结构合法 + 内容正确"，
   没有实际运行游戏看 UI 是否显示正常。**字体是否有中文字形
   并未在本机验证**（该游戏的 `fonts/analysis.jsonl` 是 0 字节，
   说明字体分析阶段没有产出内容）。
2. 只覆盖了 **1 个游戏**（103 条，全为 UI 短标签）。
   长对白、贴图文字、以及 RPG Maker / Ren'Py 等引擎的写回
   **没有**在这份记录里验证。
3. 102 条译文里有 **25 条字节数比原文长**（如 `Mask` 4 → `遮罩` 6 字节）。
   这类条目只有落在"槽位容量够"的位置才能写进去；
   容量不够时 `unity_patch` 的行为是**跳过并记录**，
   **绝不截断**（截断会造成静默内容损失）。
